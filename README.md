# Safari Media OS — Phase 1 (Ingest)

Hourly Drive-poll worker for the AI-curated media pipeline behind SWO tourism builds.
First client: Sausage Tree Safari Camp (`sausage-tree`, Build #121).

Reference briefs live on the swo/media bridge:

- `CLAUDE-SAFARI-MEDIA-OS.md` — locked decisions, status, protocols

## What this repo is

The Phase 1 worker is a one-shot ingest run, scheduled hourly by systemd timer on a Virtarix VPS in Johannesburg. It does not modify the client's Drive — read-only service-account access throughout. Originals stay where they are; the worker downloads each new image to a local cache, embeds it with CLIP (ViT-B/32, 512-dim), tags it with Claude Haiku Vision, and writes one row per image to `safariwe_media_os.assets` plus a 2048-byte BLOB embedding to `clip_embeddings`.

The Phase 2 admin panel, Phase 3 output pipeline (Sharp/ffmpeg, R2, Cloudflare Images Transformations), Phase 4 STSC integration, Phase 5 video, Phase 6 public gallery, and Phase 7 bulk import are out of scope here. They live in later builds against this same `media` project.


## What Mike needs to provision before deploying

These are the items the brief calls "Mike provides". They are the only blockers between this repo and a green ingest run.

1. **Virtarix VPS**, Johannesburg region, 2GB RAM, Ubuntu 24.04 LTS, public IPv4. Note the IP — cPanel needs it whitelisted.
2. **Anthropic API key** for Claude Haiku, dropped at `/etc/media-os/anthropic.env`, mode 600, owner `mediaos:mediaos`. File contents:
   ```
   ANTHROPIC_API_KEY=sk-ant-...
   ```
3. **Google Drive service-account JSON**, dropped at `/etc/media-os/drive-sa.json`, mode 600, owner `mediaos:mediaos`. The Sausage Tree Drive folder (ID `1f_o_JY6-ILavBygqHQLW8ru9Sa6CzHqT`) must be shared with the service account's `iam.gserviceaccount.com` address.
4. **cPanel MySQL database** `safariwe_media_os`, a user with full perms on it, and the VPS's public IP added to "Remote MySQL". Connection details go into `/etc/media-os/ingest.env` (template generated by `install.sh`).

## Deploy

On the VPS, as a user with sudo:

```bash
git clone <this-repo> /tmp/media-os-src
cd /tmp/media-os-src
sudo ./install.sh
```

The installer:

- installs Python 3.11, Node 20, ffmpeg, libvips, MySQL client libs
- creates the `mediaos` system user and `/opt/media-os`, `/etc/media-os`, `/var/lib/media-os/cache`, `/var/log/media-os`
- builds a venv at `/opt/media-os/venv` and installs `requirements.txt`
- writes a systemd unit + hourly timer
- generates `/etc/media-os/ingest.env` with placeholders to fill in
- starts the timer if both secret files are already in place

## Deploy the schema (manual, one-time)

The schema cannot be deployed by the VPS install script because cPanel owns the MySQL server. After the database exists and the VPS IP is whitelisted:

```bash
mysql -h <cpanel-host> -u <user> -p safariwe_media_os < sql/schema.sql
```

## Smoke tests (deliverables #2, #4, #5)

These are the single-image / single-call verifications the brief calls out as the first-session heartbeat. Run each on the VPS after install.

```bash
sudo -u mediaos /opt/media-os/venv/bin/python - <<'PY'
from ingest.config import load
from ingest.drive import DriveClient
cfg = load()
client = DriveClient(cfg.drive_sa_path)
for f in client.list_sample(cfg.drive_folder_id, limit=10):
    print(f["mimeType"], f["name"])
PY
```

```bash
sudo -u mediaos /opt/media-os/venv/bin/python -m ingest.clip_worker /tmp/test.jpg
```

```bash
sudo -u mediaos /opt/media-os/venv/bin/python -m ingest.vision_worker /tmp/test.jpg image/jpeg
```

The first prints 10 entries from the STSC root. The second prints `dim=512 first3=[...]`. The third prints a JSON tagging object.

## First real run

```bash
sudo systemctl start media-os-ingest.service
sudo tail -F /var/log/media-os/ingest.log
```

`MEDIAOS_BATCH_LIMIT=200` per run caps the first runs at 200 new images, easing Vision rate-limit pressure. Drop the cap (`MEDIAOS_BATCH_LIMIT=0`) once steady-state is reached.

## Phase 1.5 — CLIP validation gate

Once the STSC pool is ingested (target ~5,000–15,000 images):

```bash
cd /opt/media-os
sudo -u mediaos venv/bin/python tests/test_clip_queries.py --out /tmp/clip_gate_report.html
```

Open the HTML report. Mike judges each brief: pass = top-5 contains ≥1 obviously-correct match. Pass rule per `SAMPLE-SLOT-BRIEFS.md`:

- 5/5 pass → unlock Phase 2
- 4/5 pass → conditional, log, proceed
- ≤3/5 pass → stop, escalate
